# 对手手牌概率模型

规则 AI 在决策时不能读取暗牌和牌堆顺序，只能根据公开信息估计“对手手里可能有什么”。本模型集中在 `client/src/engine/ai-memory.ts`，留牌倾向集中在 `client/src/engine/hand-tendency.ts`。

## 输入

### 明牌

`rememberCards(state, generalIndex, cards, source)` 记录公开亮出的牌。当前覆盖：

- 五谷丰登选牌
- 火攻展示
- 伪溃亮牌
- 反间给出的牌
- 裸衣亮出的牌
- 智愚亮出的牌

`knownHand(state, generalIndex)` 只返回“记忆里亮过、此刻仍在该角色手上”的牌；牌一旦离手，记忆自动作废。明牌在 `guessHand` 里直接算作已知，不再参与概率抽样。

新增“展示手牌/亮牌”类技能时，在 `game-actions.ts` 对应结算处调用 `rememberCards`，并补一条 `[记忆]` 检查。

### 公开区域

`poolView` 用以下区域反推未知牌池：

- 弃牌堆（`state.discard`，包含已使用、已打出、已弃置的牌）
- 五谷丰登可选池（`state.harvestPool`）
- 所有角色的装备区、判定区、武将牌上的牌（`generalPile`）、忠义牌
- 己方手牌（AI 自己知道）
- 敌方明牌（`knownHand`）

处理规则：

- **按 `id` 去重**：同一张牌可能同时出现在弃牌堆和某个公开区域，只扣一次。
- **转化牌按 `originalName` 计数**：国色、断粮等把方块闪/黑桃牌放进判定区或弃牌堆时，扣的是原始牌名，不是转化后的锦囊名。
- **虚视为的牌不占实体牌**：`virtual` 牌跳过。
- **隐藏牌只减数量**：伏兵、粮等只公开“有几张”，不公开牌名；只减少 `unseen`，不进入按牌名的计数。

`PoolView` 暴露：

- `unseen`：尚未被看到的实体牌数
- `left(kind)`：某类关键牌还剩几张
- `rate(kind)`：一张未知牌属于某类的概率
- `seenCount` / `hiddenCount`：已见牌数与隐藏牌数
- `played(kind)`：弃牌堆里已使用/已弃置的关键牌数量

### 已使用/已弃置的牌

弃牌堆是“已使用/已弃置”的统一账本：使用后结算完的牌、弃牌阶段弃掉的牌、技能弃置的牌都会进入 `state.discard`。因此：

- `left(kind)` 会随弃牌堆增加而下降；
- `guessHand` 的未知手牌期望随之下降；
- 不需要按角色归属也能得到正确的剩余手牌边际分布。

`played(kind)` 只用于复盘和调试，不参与“谁打出了什么”的推断。

## 手牌概率

`guessHand(state, playerId, generalIndex)` 返回：

- `known` / `unknown` / `size`
- `expected[kind]`：整手牌里杀/闪/桃/无懈的期望张数
- `atLeastOne(kind)`：整手牌里至少有一张的概率
- `keyCardOdds[kind]`：关键牌名的期望张数（杀、闪、桃、酒、无懈、乐、兵、连弩、南蛮、万箭、五谷、桃园、决斗、火攻）
- `atLeastOneKey(kind)`：关键牌名至少一张的概率
- `knownRatio` / `confidence`：明牌比例与估计置信度
- `tendency`：本次使用的留牌权重

计算方式：

1. 明牌直接固定；`unknown = size - known.length`。
2. 未知部分按“剩余牌池密度 × 武将留牌倾向”归一化。
3. 至少一张使用无放回超几何近似（`atLeastOneChance`），不再用独立同分布。
4. 非核心牌归入 `other`，避免把四类牌的概率抬到 100%。

## 团队共享资源

桃和无懈不是个人资源：一名角色濒死时任何存活队友都能出桃救；锦囊结算时任何队友都能出无懈。只按单人手牌判断会系统性低估。

`teamResource(state, playerId, kind)` 合并敌方全队的 `guessHand`：

- `members`：参与统计的存活队友数
- `known`：全队明牌里的张数
- `expected`：全队未知手牌的期望张数
- `atLeastOne`：全队至少一张的概率，按 `1 - Π(1 - p_i)` 合并
- `hands`：全队手牌总数

使用约定：

- 判断“对面能不能救回濒死角色”用 `teamResource(..., 'peach')`；
- 判断“关键锦囊会不会被无懈”用 `teamResource(..., 'negate')`，`negateRisk` 已改为该口径；
- `guessHand` 的 `expected.peach` / `expected.negate` 只描述“这个人手里有多少”，不能代表全队。

已使用的桃/无懈仍由 `poolView` 从剩余牌池扣除，因此全队 `expected` 会同步下降；阵亡队友不计入。

## 留牌倾向

`handTendencyOf(general)` 按技能 id 返回杀/闪/桃/无懈/其他的权重，默认 1。权重只作用于未知手牌，不改变明牌。

已登记的方向：

| 方向 | 代表技能 | 权重 |
| --- | --- | --- |
| 菜刀留杀 | 咆哮、武圣、无双、铁骑、裸衣、强袭、烈弓、雄乱 | 杀 ×1.35，闪 ×0.9 |
| 闪可转化 | 龙胆、倾国、红颜 | 闪 ×1.3，桃 ×1.1 |
| 卖血/受击收益 | 遗计、奸雄、刚烈、激昂 | 闪 ×1.15，桃 ×1.15 |
| 治疗核心 | 急救、青囊、结姻 | 桃 ×1.35 |
| 装备流 | 枭姬、旋风、窃听 | 其他 ×1.2 |
| 锦囊流 | 集智、奇策、空城 | 无懈 ×1.25，其他 ×1.15 |
| 黑牌流 | 洛神、鬼道、雷击 | 闪 ×1.1，其他 ×1.1 |
| 制衡/奇制 | 制衡、奇制 | 其他 ×1.15 |
| 改判/手牌流动 | 鬼才、矫诏、连营 | 其他 ×1.1 |
| 苦肉 | 苦肉 | 桃 ×1.15 |

新增武将时：

1. 在 `hand-tendency.ts` 的 `RULES` 里补一条技能 id 与权重；
2. 不要按武将整体强度加权重，只登记“会让留牌结构偏离牌池密度”的技能；
3. 权重限制在 0.75–1.6，避免单类牌被抬成必留。

## 已知限制

- 权重是启发式，不是统计拟合；它改善方向，不保证每局都更准。
- 弃牌堆重洗后，`unseen` 以 1 为下限，牌池密度会偏保守。
- 暗置的武将牌、未登记的展示技能不会被读牌面；只可能被计入 `hiddenCount`。
- 不区分“哪个对手用了哪张牌”，只维护全局剩余牌池；这对剩余手牌的边际分布足够，但无法回答“这个对手刚才为什么弃闪”。
- `confidence` 目前等于明牌比例，空手牌视为完全确定；没有把对手的历史出牌习惯纳入。

## 验证

```bash
cd client
npm run check
```

`[记忆]` 段覆盖：明牌固定、明牌离手作废、弃牌堆压低密度、同一张牌只扣一次、转化牌按原牌名、超几何至少一张、技能留杀倾向、已弃置的闪压低剩余手牌期望、团队桃/无懈合并、已使用的桃压低全队期望、阵亡队友不计入。
