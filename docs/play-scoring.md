# 出牌阶段评分体系

规则 AI 的出牌阶段按固定五步走：

1. 枚举所有可用牌与主动技能，每个动作带上执行闭包；
2. 给每个动作算预设优先级（这张牌本身值多少）；
3. 叠加局面相关的动态修正；
4. 拆成「收益 - 风险 + 战略权重」；
5. 按回合总收益期望排序，执行最高分动作；执行后重新进入第 1 步。

实现集中在 `client/src/engine/ai-policy.ts` 与 `client/src/engine/local-ai.ts` 的 `aiPlayOne`。

## 目标层

出牌前先识别一个最高优先级目标（`client/src/engine/ai-objective.ts`），候选动作围绕它排序：

| 目标 | 触发条件 | 推荐序列 | 优先级 |
| --- | --- | --- | --- |
| 斩杀核心 | 敌方主帅/核心进入斩杀线 | 酒 → 杀 → 决斗/火攻 → AOE | 120 / 100 |
| 解除队友延时 | 队友判定区有乐/兵粮/闪电 | 拆 → 顺 | 105 / 95 |
| 限制高威胁敌人 | 敌方下回合威胁最高且未被延时 | 乐 → 兵粮 → 拆 → 顺 → 借刀 | 85 |
| 保护残血队友 | 队友体力 ≤ 2 | 桃园 → 五谷 → 防具 | 75 |
| 常规集火 | 没有更紧急目标 | 酒 → 杀 → 决斗/火攻 → AOE | 55 |

目标匹配的动作按 `priority × 0.25 × (1 - 序列位置 × 0.1)` 加分，最高约 30 分；只改变排序，不替代动作本身的收益/风险评分。执行一个动作后重新识别目标，所以“先拆乐、再贴乐、最后集火”会按局面自然衔接。

`PlayTrace.objective` 记录本次使用的目标、原因与推荐序列，复盘时能看到 AI 这一回合“想做什么”。

## 动作评分

```text
immediate = preset + gain - risk + strategic
```

| 项 | 含义 | 来源 |
| --- | --- | --- |
| `preset` | 预设优先级 | `BASE_SCORE`：无中生有 90、乐不思蜀 70、顺手 65、拆桥 60、决斗 55、杀 50 |
| `gain` | 收益：目标状态变化 | 期望伤害、弃牌、失去装备、被延时控制、AOE 净掉血 |
| `risk` | 风险：自身暴露与手牌消耗 | 关键牌机会成本、藤甲浪费、为前置动作压后、拆集火目标的反向风险 |
| `strategic` | 战略权重 | 集火偏移、斩杀窗口、节奏、保核、威胁排序 |

`estimateAction({ preset, gain, risk, strategic })` 返回 `immediate`。没有单独拆分的技能动作把差额记入 `strategic`，总分与旧实现一致。

## 收益预测

- **杀**：`predictSlash` 先按目标明牌与剩余牌池估闪避率，`gain` 取期望伤害；斩杀概率进入 `strategic`（主帅与边锋权重不同）。
- **拆牌**：`dismantleGain` 按后续集火价值排序——拆集火目标的 `+1 马` 最高，其次防具、判定区延时、最后是手牌见底的目标。
- **顺手**：按目标手牌的平均保留价值估收益，明牌越多、手牌越少越容易偷到关键牌。
- **决斗 / 火攻**：用 `predictDuel` / 花色覆盖估命中，命中率直接进 `gain`。
- **群体锦囊**：`predictAoe` 的双方净掉血进 `gain`，敌方团队无懈风险进 `risk`。
- **延时锦囊**：判定成功率进 `strategic`，敌方无懈风险进 `risk`。

## 回合总收益期望

```text
turnValue = immediate + 0.35 × (
              0.85 × 同计划最高动作
            + 0.70 × 同计划次高动作
            + 0.55 × 同计划第三动作
            + 0.50 × 跨计划最高动作
          )
```

同一条计划内的动作能连起来（例如先贴乐再出杀），比一个孤立的高分动作更值得先走。后续收益整体乘 0.35，只用于在接近的候选之间排先后，不让低分动作靠后续高分反超。排序用 `turnValueOf`，`PLAN_BONUS` 仍然只用于打破同分。

执行一个动作后，`aiAct` 重新进入 `aiPlayOne`，用最新手牌与公开信息重新评分；因此这里算的是「当前局面下这一动作能带出的整条线」，不是一次性规划整回合。

## 复盘字段

`PlayTrace.candidates` 与 `listPlayOptions` 都带 `gain` / `risk` / `strategic` / `turnValue`，对局日志可以直接看到某个动作为什么排在前面。

## 边界

- `preset` 与 `immediate` 都是同一回合内的相对分，不是绝对收益。
- 补丁层（`ai-variant.ts`）仍可改分或否决候选；补丁改分只改 `score`，不重算收益分解。
- 收益预测依赖 `ai-memory` 的明牌与牌池估计；暗牌不可读。
